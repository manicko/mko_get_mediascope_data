## Constraints

1. One Implementor at a time; max 2 parallel subagents; no background launches.
2. Production code is king — never distort production code for tests. TST-012 changes
   production code because the timeout/exception isolation is a genuine bug fix (PIPE-002/006/007).
3. English-only comments, logs, docstrings.
4. No `print()` in core modules.
5. Enums for all fixed values in test fixtures.
6. All tests must be hermetic (no real user-config dir writes).

## Key Risks

1. **TST-012**: Modifying `worker()` changes the core async pipeline. Must preserve existing
   behavior for the happy path (success → CSV written, task_done called) while adding timeout
   + exception isolation. The lifecycle test must still pass after the change.
2. **TST-010**: Setting `--cov-fail-under=70` will fail CI if coverage drops below 70%.
   Must choose threshold at current level (70%) to avoid breaking CI immediately.
3. **TST-009**: Testing the default `max_attempts=10` requires a function that fails 10 times.
   Use `sleep_time=0` and mock `asyncio.sleep` to keep the test fast.

### Block C — TST-012: Worker Timeout + Exception Isolation (HIGH risk)
**Priority:** HIGH
**Risk:** HIGH (production code change to core async pipeline)
**Agents required:** Planner (pre-implementation design) → Implementor

**Design (pre-approved from findings):**
1. Extract task processing into `_process_item(item)` helper
2. Add `timeout: float | None = None` parameter to `worker()`
3. Wrap `_process_item` call in `asyncio.wait_for` when `timeout` is set
4. Use `try/except/finally`: catch `asyncio.TimeoutError` and general `Exception`
5. Always call `task_done()` in `finally` block (prevents M11-class hang)
6. On exception/timeout: set `item.status = False`, `log_error = True`, write error YAML
7. Propagate `timeout` from `create_report(timeout)` → `processing_tasks(timeout)` → `worker(timeout)`

**Actions:**
1. Refactor `worker()` in `reports.py` (lines 134–153) with try/except/finally
2. Add `_process_item()` helper method
3. Add `timeout` parameter to `worker()`, `processing_tasks()`, `create_report()`
4. Add `test_worker_does_not_hang_on_timeout` to `test_reports_lifecycle.py`
   — doubles `wait_task` to never return terminal status, asserts worker
   completes within a bounded wall-clock time and task is marked failed

**Acceptance criteria:**
- Existing lifecycle test (`check_done=False`) still passes with same CSV output
- New timeout test completes within 10s wall-clock (does not hang)
- `task_done()` always called even on exception (no `queue.join()` hang)
- Mutation M11 (task_done removal) would be caught by new test
